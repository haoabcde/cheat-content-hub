# 公众号成稿前置工作流

这份协议解决一个具体问题，公众号文章不能一上来就写正文、找几张图、渲染 HTML。成稿前必须先把读者为什么愿意点开、为什么愿意继续看、图为什么放在这里讲清楚。

适用场景：
- 用户要写公众号长文、AI 日报、论文解读、产品发布解读；
- 用户给了对标文章、公众号链接、封面截图或说「参考这个排版」；
- 用户反馈封面不想点、图片太少、配图不丰富、图注不像给读者看的、HTML 不能直接复制图片。

## 停止规则

如果用户明确说「现在不做公众号文章创建」「先改工作流」「不要继续写稿/渲染/发布」，立刻停止文章产物推进，只修改流程、模板、脚本或检查器。

不要继续改正文、不要渲染、不要发草稿箱。已经产生的本地草稿只报告状态，不擅自回滚。

## 强制阶段

### 1. 事实源先行

写作前先建立事实源，优先级是原始论文、官方博客、官方文档、项目页、GitHub、作者或机构的原始发言。媒体报道和对标公众号只能作为角度参考，不能替代事实源。

如果对标文章和原始材料冲突，正文采用原始材料，并在内部记录冲突点。

推荐产物：
- `research/sources.md` 或 `visual/sources.md`
- 原始链接、截图来源、关键数字、存在争议的点

### 2. 对标拆解先于写稿

用户给了参考文章或反馈「别人同题更想看」时，必须先做 `layout-audit.md`，再改正文。

`layout-audit.md` 至少回答：
- 封面为什么更想点，是人物/场景/冲突/数字/标题哪一项在起作用；
- 首屏前 5 段怎么推进，冲突出现得有多早；
- 小标题、强调色、引用块、列表、留白和段落密度怎么用；
- 图片在第几段出现，图片之间平均隔多少字；
- 图注是给读者解释，还是像素材备注；
- 哪些只借鉴，不照搬；
- 我们这篇要改哪 5 个具体点。

禁止只说「参考它的风格」。必须落到可执行的版式和内容动作。

### 3. 视觉方案先于正文定稿

公众号文章不是写完再塞图。写正文前或初稿后第一轮，必须先做视觉方案。

推荐产物：
- `visual/sources.md`，每张图的来源和支撑观点；
- `visual/captions.md`，每张图给读者看的图注；
- `cover-prompt.md`，横版封面提示词；
- `visual/contact-sheet.jpg`，方便一次看完图片质量。

图片密度建议：
- 2000 字以内，至少 4 张图；
- 2500 到 4500 字，至少 6 到 8 张图；
- 4500 字以上，每 350 到 500 个中文字附近要有一次视觉停顿；
- 第一张正文图必须在前 20% 内容内出现，最好直接承接开头冲突。

配图必须有角色，常见角色是：
- 锚点图，证明事件真的发生；
- 冲突图，让读者看到问题或失败；
- 数据图，支撑核心数字；
- 机制图，解释为什么会这样；
- 人物/场景图，让文章不全是表格和截图；
- 收束图，把结论落回一个判断。

### 4. 裁切和可读性

截图不是整页留档。截图服务正文，必须让手机读者看得清。

硬要求：
- 裁掉浏览器空白、侧栏、无关评论、无关导航；
- 重点信息放大，保留最小必要来源上下文；
- X/微博/公众号截图保留作者、账号、正文、日期或来源身份；
- 数据表保留列名和行名，不截孤立数字；
- 论文图优先裁核心区域，必要时重做简化图；
- 禁止为了好看做无信息量 UI 卡片；
- 禁止用图注解释给编辑看，要像正文的一句话给读者看。

图注写法：
- 先告诉读者看哪里；
- 再告诉读者它说明了什么；
- 不写「来源截图」「如图所示」「该图展示了」这种素材备注。

### 5. 正文再写

正文可以用个人化、口语化风格，但不等于碎成很多短句。公众号正文应当有手机阅读节奏，同时避免一屏只有三四个短段。

默认要求：
- 开头 3 到 6 段内出现冲突和核心结果；
- 不用报告腔小标题，除非文章已经很长且读者需要路标；
- 小标题要像人说的话，不要像科技商业翻译；
- 段落按意思合并，避免每句话都单独成段；
- 资料解释要嵌进叙述里，不要写成论文摘要。

### 6. 渲染和复制验证

给用户 HTML 前，必须产出两份：
- `draft.wechat-article.html`，正常预览版；
- `draft.wechat-article-copy.html`，图片转成 data URI 的复制版。

HTML 正文默认采用「编辑正文」排版，而不是普通 Markdown 直译：
- 正文左右留边，段落行高接近 2；
- H2 用左侧竖线，作为真正分节；
- 引用块用于重要判断和金句，不用于普通解释；
- 图片上下留足空间，图注紧贴图片且左对齐；
- 每 600 到 900 字附近要有一次视觉或版式停顿；
- 参考资料区要弱化，不抢正文结尾。

验证项：
- copy 版 HTML 里的本地图片已经变成 `data:image/...;base64,...`；
- 所有图片路径存在；
- 图注在 HTML 里可见；
- 图片数量和正文长度匹配；
- H2、引用、图片、分割线形成阅读节奏，不是一整屏连续灰字；
- 没有缺图、拉伸、过小、图文错位；
- 标题和封面提示词一致。

### 7. 发布另走确认

渲染完成不等于发布。发到公众号草稿箱前必须再次获得用户明确确认。

如果凭证缺失，直接说明缺哪个字段，转为手动复制流程，不要假装已经能发布。

## 成稿定义

一篇公众号文章只有同时满足这些条件，才算准备好让用户复制或确认发布：
- 事实源核过，关键数字没有只来自二手文章；
- 有 `layout-audit.md`，如果用户给过参考文章；
- 有横版封面方案或封面提示词；
- 有足够数量、裁切清楚、移动端可读的图片；
- 图注像给读者看的，不像给编辑看的；
- 正文不是 AI 报告腔；
- HTML 不是普通段落流，有清晰的正文节奏；
- copy HTML 可以带图复制。
