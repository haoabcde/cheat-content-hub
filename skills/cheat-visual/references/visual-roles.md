# Visual Roles

Each recommended visual must have one role.

## Anchor visual

Confirms the event or feature exists. Examples: official announcement, product page, paper title, release note, GitHub release.

Use near the beginning of the article.

## Friction visual

Shows why the story is not a clean press release. Examples: bug report, user complaint, confusing UI, pricing wall, rate limit, failed workflow, error message.

Use in hands-on review, skepticism, and pitfall sections.

## Explanation visual

Makes a mechanism easier to understand. Examples: MCP flow, agent workflow, RAG pipeline, before/after diagram.

Can be self-made. Must be labelled as self-made and not treated as source evidence.

## Comparison visual

Lets readers judge differences quickly. Examples: plan comparison, model comparison, old vs new workflow, feature table.

Use in decision-making sections.

## Sentiment visual

Shows community mood. Examples: X reactions, HN comments, Reddit comments.

Use sparingly. It adds human texture but is weak evidence.

## Decision visual

Helps readers decide what to do. Examples: "适合交给 AI / 不适合交给 AI" table, risk checklist, adoption matrix.

Usually self-made and suitable near the end.
